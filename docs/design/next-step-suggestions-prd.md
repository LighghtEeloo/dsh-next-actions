## 0. 理想形态速览

**一句话**：回答结束后，紧接着出现一张与官方动作卡**结构完全相同**的卡片——先用一两句话承接刚才的结果，
默认再给出 3 个可点的下一步（模型给 1–6 条，其余收进「还有 N 条」）；点一下，那条完整指令**填入输入框**，
你改完自己按发送；不点，就当没看见。

```text
助手回答（正文）……
[▸ 工具过程组 · 折叠]
      └ 下一步建议 · 已生成                      ← 一行式调用记录（同官方卡）

┌──────────────────────────────────────────────────────────────┐
│ ▣ 修复已完成，改动集中在 src/api。接下来可以验证行为，或补一个     │
│   回归用例防止回退。                                             │
│ [ 跑一下测试 ]  [ 加一个回归用例 ]  [ 看改动 diff ]   还有 1 条   │
│ 已填入输入框，可修改后发送                     [ − 暂不需要 ] │
└──────────────────────────────────────────────────────────────────┘

┌ 官方动作卡（形态相同，位于其下）─────────────────────────────────┐
│ 标题                                                            │
│ 说明（过长折叠 + 展开）                                          │
│ （控件）（状态行）                                               │
│ [ 暂不需要 ]                                                    │
└──────────────────────────────────────────────────────────────────┘

（消息操作行：复制 / 重试 / 分支 …）
```

> 预览默认收起：悬停/聚焦某个建议时，按钮行下方出现「将填入」+ 该条完整指令，移开/失焦收起。

**五条设计原则**

1. **先承接，再提议**：卡片必须先有一两句上下文，说明「刚才发生了什么、为什么这几步是自然的」，
   建议不能凭空跳出。
2. **可选**：不点 = 零副作用；不占输入框、不打断对话、不自动执行；可单轮忽略、可全局关闭。
3. **可改**：点击只「填入」，不「发送」；填进去的话你随时能改、删、再写，发送前永远有一次人工确认。
4. **严格同款（三处功能例外）**：卡片与过程组行照抄官方动作卡——容器、折叠说明、控件区、状态行、
   一行式调用记录、可达性命名；只保留三处有意差异：无可见标题（品牌小标代替、`aria-label` 仍叫
   「下一步建议」）、忽略/恢复收进状态行右侧的带文字切换按钮、预览默认收起并在悬停/聚焦时出现。
   不自创右上角关闭、浮层、摘要收起等官方卡没有的形态。
5. **不打扰**：没东西可建议就不出卡；不重复回答正文；不寒暄、不推销、不承诺。

## 1. 需求

### 1.1 一句话需求

> 在每条回复末尾，**可选地**给出「下一步可以做什么」；每条都带一段承接上下文；点一下把指令填进输入框，
> 修改后自己发送；不点不影响任何事，也不额外花钱。

### 1.2 需求条目

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| R1 | **落点正确** | 回合尾部、最终回答之后；思考/工具过程组折叠后仍可见 | P0 |
| R2 | **上下文先行** | 卡片说明区先写 **1–2 句简短上下文**（承接刚才的结果），使按钮不唐突 | P0 |
| R3 | **点击=填入** | 点击建议 → 完整指令**填入输入框**，光标就位、可编辑；**不自动发送** | P0 |
| R4 | **可选** | 不点=零副作用；可单轮用状态行右侧「暂不需要」忽略、再用「恢复建议」恢复，可全局关闭；不占输入框、不自动执行 | P0 |
| R5 | **数量与角度** | 默认展示 3 条（模型给 1–6 条，其余收进「还有 N 条」；设置可选 Auto 或固定 1–6）；同轮角度不重复；可标 1 条「推荐」置顶 | P0 |
| R6 | **形态严格一致（三处功能例外）** | 卡片：折叠说明/控件区/状态行/可达性命名与官方卡一致；三处例外：无可见标题（上下文行行首 16px 品牌小标，`aria-label` 仍为「下一步建议」）、忽略/恢复改为状态行右侧带文字的切换按钮、预览按需显示（默认收起） | P0 |
| R7 | **位置在上** | 建议卡位于官方动作卡**上方**，紧跟回答正文 | P0 |
| R8 | **草稿安全** | 输入框已有内容时**不得静默覆盖**；提供「追加到末尾 / 替换 / 取消」，追加为主操作 | P0 |
| R9 | **语言** | 上下文句与按钮文案跟随用户当前语言；界面文案随界面语言 | P1 |
| R10 | **危险标记** | 破坏性/不可逆建议必须有警示与「需确认」标记；点击同样只填入，永不自动发送 | P0 |
| R11 | **持久与回放** | 刷新、重启、回放、fork 后卡片、状态与过程组行都在（与官方卡一致，不做自定义收起形态） | P1 |
| R12 | **场景收敛** | 子代理/团队内部会话、定时任务默认不出现；P1 起 Host 对子代理连工具声明与提示词都不注册（省 364 tokens/子代理请求） | P1 |
| R13 | **可观测** | 卡片被看到/被点击/被忽略的本地统计，仅本机可见 | P2 |
| R14 | **过程组一行式** | 工具过程组里该调用只占一行（标题 + 状态摘要）；仅未显示/中断可展开原因；「查看调用」；行内无操作按钮——与官方卡 `propose_action` 行完全一致 | P0 |
| R15 | **稳定触发** | 有真实后续动作的实质回复由**常驻系统提示**引导模型调用工具（不依赖会话里攒下的使用习惯——首次 compact 后模型就不再主动调用）；回复本身就是下一步清单时，也交给卡片、正文只留引子；寒暄、简单确认、纯知识问答、无下一步的回复不触发，宁缺毋滥。v4（2026-11-09）：触发条件改成模型可自查的客观清单（任务完成/推进、跑过工具、改过文件、验证/审查/审批待办、本来要以清单结尾），不确定分两档（工作回合仍调用 2–3 条、琐碎/社交跳过），并跳过「只重复上一张卡片」与「已弹结构化提问」的回合（tech §5.7.1） | P0 |
| R16 | **Token 门控** | 子代理请求不付工具声明（P1：根 agent `when`）；Host 配置 `enabled:false` 时同时不注册 tool 与常驻提示（0 常驻 token），卡片总开关从客户端 localStorage 移到 Host config；「工具首次使用后再激活」方案先评估、A/B 后再定（tech §5.7.2） | P1 |

### 1.3 需求边界（明确「不是什么」）

| 容易混淆的东西 | 我们的关系 |
|---|---|
| 输入框 ghost text 补全 | **不是**。不占输入框、不在输入框上方显示、不按 Tab 采纳。 |
| 官方动作卡（个性化推荐） | **不是同一个功能**：它是「创建个性化页面 / 启用内置插件」的提案卡；我们**严格照抄它的形态**（卡片 + 过程组行），内容是「下一步动作」，点击是填入输入框。 |
| 自动执行 / 自动发送 | **不是**。点击只填草稿，发送永远由用户完成；2026-11-10 起不再提供直发选项。 |
| 回答正文里的「接下来可以…」 | **不是**。建议不进正文、不参与 Markdown 复制。 |
| 定时任务 / 主动推送 | **不是**。只在对话回合结束时出现。 |
| 卡片渲染框架 | **不是**。只做一种内容，不造通用 UI 体系；样式全部沿用官方卡。 |

## 2. 场景

**A · 验证下一步**
改完 bug 后，卡片：“修复已完成，改动集中在 `src/api`。接下来可以验证行为，或补回归用例防止回退。”
用户点「跑一下测试」→ 指令填进输入框，光标在末尾；用户把「跑一下测试」改成「只跑 api 相关测试」再发送。

**B · 多方案选择**
卡片：“三个方案都可行，差别在迁移成本。可以先验证成本最低的方案，或补做一次基准测试再定。”
用户点「先验证方案 B」→ 填入草稿；用户删掉一句、加上约束后发送。

**C · 不想要时**
点状态行右侧「− 暂不需要」→ 控件收起、状态行显示「已忽略」，卡片本身保留；同一位置换成「+ 恢复建议」，点它恢复建议。
过程组里的一行仍是「已生成」（它记录调用结果，不记录你的选择）。
或去设置里全局关闭。之后不再打扰。

**D · 危险动作**
卡片：“改动已经完成，发布前还需要确认回归结果。”
按钮「提交并推送」带「需确认」标记；点击后填入草稿并附提示：“该操作可能不可逆，确认后发送。”
用户检查后自己按发送——**任何情况下都不会被自动发出去**。

**E · 隔天回看**
历史轮次的卡片保持原样，状态行记录「已填入」「已忽略」等状态；过程组行仍是「已生成」；
随时可以再次点击填入，与官方卡的历史表现一致。

## 3. 卡片与过程组行形态

### 3.1 在会话流中的位置

从上到下：**回答正文 → 工具过程组（可折叠，内含一行「下一步建议 · 已生成」）→ 下一步建议卡 → 官方动作卡（如出现）→ 交付/计划/定时卡片 → 消息操作行**。

- 建议卡紧跟回答，位于官方动作卡之上；与官方卡同宽、同间距、同圆角；
- 只在本轮**以文本回答结束**时出现；纯工具轮、中断轮、出错轮不出现；
- 每轮最多一张（与官方卡同一规则）；
- 卡片帧完全沿用官方动作卡：本卡只提供内容（品牌小标、说明、控件、状态行），不参与帧的样式定义。

### 3.2 卡片结构（与官方卡逐项对齐）

| 区域 | 内容 | 说明 |
|---|---|---|
| 品牌小标（代替标题） | 16px 列表小标 | 位于上下文行行首（原「下一步建议」加粗标题行不再显示）；`aria-label` 仍为「下一步建议」 |
| 说明（brief） | **1–2 句上下文**，承接刚才的结果 | 官方卡同一折叠说明组件：紧凑空白、超宽折叠、ghost 小按钮「展开/收起」、不改全文 |
| 控件区 | 默认 3 个建议按钮（模型给 1–6 条时其余收进「还有 N 条」）；推荐项在最前、primary 并带「推荐」内联标记；每个 chip 最多一个内联标记（需确认 > 已填入 > 推荐）；可跳过类建议排最后、不单独标记；冲突态只放「将填入 / 当前草稿」对比框，动作按钮进状态行 | 官方卡 body 的控件区，使用同一套标准按钮规格 |
| 折叠 | 「还有 N 条」就地铺开，再点「收起」 | 与官方卡折叠控件同一画法（ghost 小按钮） |
| 状态行 | 「已填入输入框，可修改后发送」/「输入框已有内容」/「已忽略」/ 危险警示 /「输入框暂不可用」 | 官方卡同一 status 行位置（`role=status`） |
| 冲突态 | **状态文字与动作同一行** | 「输入框已有内容」与「追加到末尾（primary）/ 替换 / 取消」并排放进状态行（窄列可换行），不设独立动作行；控件区只剩对比框（高度预算见 §8） |
| 忽略 / 恢复 | **状态行右侧带文字的 ghost 小按钮** | 取代官方卡底部 footer 的「暂不需要（Not now）」；建议态「− 暂不需要」（沿用官方文案），已忽略态「+ 恢复建议」（v0.8 起的对偶文案）；点前者控件收起、状态行「已忽略」，点后者恢复 |
| 预览 | **按需出现的指令预览** | 默认收起；hover / focus 某个建议时在按钮行下方显示「将填入」+ 该条完整指令（两行 clamp），移开/失焦收起；官方卡没有此元素（有意新增，见 §8） |

> 文案直接采用官方卡现有文案：`暂不需要 / Not now`、`已忽略 / Dismissed`、`展开 / Show more`、
> `收起 / Show less`、`查看调用 / Inspect call`——不另起一套说法。

### 3.3 与官方动作卡逐项对照（严格照抄，三处功能例外）

| 维度 | 官方动作卡 | 本卡片 |
|---|---|---|
| 容器 | 独立卡片 section（圆角、描边、内边距、内容列宽） | **完全同款**，沿用同一套 `--dsw-*` token |
| 标题 | body 头部加粗标题 | **无可见标题**（三处有意差异之一）；改为上下文行行首 16px 品牌小标，`aria-label` 不变 |
| 说明 | 折叠说明：约 260 拉丁字宽后折叠（中文按双宽计），ghost 小按钮展开/收起 | **完全同规则**，上下文句沿用同一折叠说明组件 |
| 控件 | body 自带控件区，标准按钮规格 | 建议按钮使用同一套规格，位于控件区；状态信息用文本内联，不用官方 Tag 胶囊 |
| 状态行 | `role=status` 状态行，显示 dismissed 等状态 | 同位置同样式，显示「已填入 / 已忽略」等；冲突态下状态文字与三个动作在同一行 |
| 关闭 | **底部 footer 幽灵小按钮「暂不需要」** | **有意差异**：收进状态行右侧，变为带文字的 ghost 小按钮；建议态「− 暂不需要」忽略，忽略态「+ 恢复建议」恢复 |
| 预览 | 无 | 按需预览：hover/focus 时在按钮行下方显示「将填入」+ 完整指令（有意新增） |
| 命名 | 卡片以标题命名可读区域（`aria-label`） | 以「下一步建议」命名，同规则 |
| 出现时机 | 回合结束且有文本回答；每轮一张 | 同规则；位于官方卡上方 |
| 展开/折叠/展卡 | 不产生任何模型请求 | 同规则 |

> 设计意图：不是"相似"，而是**同一张卡的不同内容**。用户不应看出两套样式；
> 三处有意差异（品牌小标代替标题、状态行带文字切换代替 footer、按需预览）都是功能推进的结果——
> 没有右上角关闭、没有浮层、没有"发送后收起为摘要"这类自创形态。
> 「推荐」「已填入」「需确认」是按钮内的单个文本标记，每 chip 至多一个；所有建议本身都是可选的，
> 因此不再显示「可以不做」。

### 3.4 视觉规格

- 宽度、内边距、圆角、描边、背景、卡片间距、说明/按钮字号全部沿用官方动作卡；
- 无标题行；品牌小标 16px 与上下文同行，上下文 13px/1.6、`label-secondary`；
- 状态行左侧文字 12px/1.6；右侧切换按钮高 28px、12px 文字 + 16px 图标（「− 暂不需要」/「+ 恢复建议」）；卡片没有 footer；
- 冲突态：对比框沿用 12px/1.6 两行信息；状态行上边距收紧为 8px，状态文字与三个 28px 动作按钮同排（窄列可换行），不另起动作行；748 列实测默认 134px → 冲突 158px（差 24px，验收 ≤25px）；
- 预览默认不占位，悬停/聚焦时出现在控件行下方：小圆角、模块底色、12px/1.6、最多两行；「将填入」前缀 11px 三级文字；
- chip 内标记 11px 二级文字，每 chip 至多一个；危险标记带 12px 警告图标（`--dsw-alias-state-warn-primary`），文字仍用二级色；
- 不新增颜色、阴影、边框或动效类型；
- 说明 2 行以内为主（超长按官方规则折叠）；控件行可换行；
- 暗色模式、`prefers-reduced-motion` 行为与官方卡一致。

### 3.5 过程组的一行式表现（严格同 `propose_action` 行）

工具调用在**工具过程组**里只占一行，与官方卡 `propose_action` 的调用行同构：

```text
[▸ 工具过程组 · 折叠]
      下一步建议 · 已生成                                   ← 正常：一行，不可展开
      下一步建议 · 未显示                              ▾     ← 异常：可展开看原因
          ┌────────────────────────────────────────────┐
          │ 本次未生成可展示的建议（原因：…）            │  ← 同款原因框
          └────────────────────────────────────────────┘
          查看调用                                        ← 同款「查看调用」链接
```

| 维度 | 官方 `propose_action` 行 | 本插件的行 |
|---|---|---|
| 行结构 | 一行 `DisclosureRow`：行首标题 + 状态 + 标题摘要 | **完全同构**：行首「下一步建议」+ 状态 + 摘要（如「3 条」） |
| 行首标题 | 「操作卡片 / Action card」 | 「下一步建议」 |
| 状态文案 | 正在准备卡片 / 正在提议 / **已提议** / **未显示** / 已中断 | 正在准备建议 / 正在生成建议 / **已生成** / **未显示** / 已中断（同位置、同顺序） |
| 标题摘要 | 卡片标题，单行省略 | 本次建议摘要（如「3 条建议」），单行省略 |
| 可展开条件 | 仅当调用失败/被拒（有原因）时展开 | **完全一致**：仅「未显示 / 已中断」等异常可展开 |
| 展开内容 | 原因 `pre` 框（同款底色/字号/圆角/内边距）+「查看调用」 | **完全一致** |
| 展开交互 | 整行可点展开；展开后保留内容 | **完全一致** |
| 行内操作 | 不承载建议按钮，只表达调用结果 | **完全一致**：不出现任何建议按钮或用户动作 |
| 与卡片的关系 | 行记录调用结果，不随卡片 dismiss 改变 | 同：用户点「暂不需要」只改卡片状态行，行仍是「已生成」 |

- 过程组折叠时，行随过程组一起隐藏；展开过程组即可看到——与官方卡一致。
- 行内状态不表达用户的选择（填入/忽略），只表达调用本身：准备中、生成中、已生成、未显示、已中断。
- 没有建议（模型未给出或全被清洗）时：**卡片不出现**，过程组行显示「未显示」，可展开看原因。

### 3.6 内容示例

**中文（任务收尾）**

> ▣ 改动已经写完并通过类型检查。接下来可以跑一次全量测试，或者先补一条针对边界值的用例。
> `[ 跑全量测试 ]` `[ 补边界用例 ]` `[ 看完整 diff ]`　还有 1 条
> （状态行：「已填入输入框，可修改后发送」）
> （状态行右侧：`[ − 暂不需要 ]`）

**中文（调研回答）**

> `[ 先跑最小链路 ]` `[ 对比候选源 ]` `[ 记录结论 ]`

**English（收尾）**

> edge value.
> `[ Run the tests ]` `[ Add a regression case ]` `[ Review the diff ]`

## 4. 核心体验 A：上下文句（防唐突）

### 4.1 结构与写法

一句话公式：**先回望，再引出**。

1. **回望**（半句到一句）：刚才完成了什么、当前处于什么状态、有什么已知限制/风险；
2. **引出**（半句）：接下来大致有哪几个方向（不必逐条复述按钮）。

规范：

| 项 | 要求 |
|---|---|
| 长度 | 中文 1–2 句、≤ 60 字；英文 1–2 句、≤ 30 词 |
| 语言 | 跟随用户当前对话语言，与按钮文案一致 |
| 语气 | 平静、具体、像同伴提醒；不用「我建议您」「希望对您有帮助」；不用感叹号 |
| 依据 | 必须来自本轮对话与真实结果（改了哪些文件、跑没跑测试、有没有风险） |
| 禁止 | 不重复回答正文的原句；不推销；不承诺结果；不写与按钮无关的内容 |
| 位置 | 卡片首行（品牌小标 + 上下文，控件区上方）；不进入回答正文 |

### 4.2 好 / 差示例

| | 示例 | 问题 |
|---|---|---|
| 差 | `[ 跑一下测试 ] [ 重新部署 ]` | 没有上下文，建议凭空出现 |
| 差 | “我已为您完成了全部工作！您还可以考虑很多事情。” | 寒暄、空泛、没信息 |
| 好 | “改动已完成，目前只跑了类型检查。可以先跑测试确认行为，或补一条回归用例。” | 回望真实状态 + 自然引出两个方向 |
| 好 | “调研结论支持「不做签名/登录」。下一步可以先把最小链路跑通验证假设。” | 点明结论，再给方向 |

### 4.3 兜底与折叠

- 上下文句是**必出**内容，不作为可选配置项关闭——它就是防唐突的核心；
- 模型没有给出或内容不合格时，使用一句本地兜底（如「本轮任务已完成，接下来可以：」），
  不显示空卡片、不显示残缺的半句；
- 上下文句过长时**完全按官方动作卡的折叠规则**处理：按字符宽度折叠、幽灵小按钮展开/收起、不改变全文、
  不撑高卡片。

## 5. 核心体验 B：点击填入

### 5.1 默认行为（空输入框）

1. 点击建议 → 该条**完整指令**写入输入框（整段替换草稿）；
2. 输入框获得焦点，光标在末尾；
3. 卡片状态行提示「已填入输入框，可修改后发送」，该建议 chip 同时显示单个「已填入」内联标记；
   提示与标记一直保留到草稿被修改、清空或发送（以草稿为准）；
4. **不发送**。用户修改后自己按发送。

### 5.2 输入框已有内容时（冲突保护）

不静默覆盖。在官方卡已有的「控件区 + 状态行」结构内就地处理：

- 控件区换成对比框：「将填入」目标指令与「当前草稿」各一行（单行省略）；
- 状态行左侧提示「输入框已有内容」，右侧三个小按钮 `[ 追加到末尾 ]`（primary）`[ 替换 ]` `[ 取消 ]`，
  与状态文字**同一行**（窄列可换行），不另起动作行；
- **追加到末尾**：把建议接在现有草稿末尾，空一行分隔；合并结果视为用户草稿，下次点击重新确认；
- **替换**：用建议整段替换现有草稿（可撤销）；
- **取消**：什么都不改，卡片恢复常态。

三种选择都只填入、不发送；冲突态不提供任何直发路径。紧凑布局把冲突态高度控制在默认态之上约 24px
（748 列实测：134px → 158px，验收上限 25px），切换状态时卡片不产生明显跳变。

### 5.3 连续点击与状态

- 若当前草稿正是上一次由建议填入、且用户**没有编辑过** → 点击另一条直接替换，不再询问；
- 若用户已经编辑过草稿 → 视为用户内容，走 5.2 的确认；
- 重复点击同一条建议 → 重用同一段文本并聚焦输入框，不重复插入；
- 当前草稿仍等于某条建议的指令时，该 chip 显示单个「已填入」标记；标记随草稿变化消失，同一轮可多次切换。

### 5.4 卡片状态与去留（严格同官方卡）

- **卡片始终保留在本轮尾部**，不新增"发送后收起为一行摘要"的形态（官方卡没有）；
- 所有变化通过官方卡已有的**状态行**表达：`已填入输入框，可修改后发送` / `输入框已有内容` / `已忽略`；
- 「已忽略」不是终点：状态行右侧的「− 暂不需要」变成「+ 恢复建议」，点一下恢复控件与状态（忽略 → 恢复可逆）；
- 刷新、重启、回放、fork 后卡片与状态保持（与官方卡一致）；
- 官方卡的「无控件时只剩关闭控件」兜底不适用于本卡：本卡没有合格建议时整卡不出（§6.4），
  过程组行显示「未显示」并可展开原因（§3.5）。

### 5.5 危险建议

- 按钮带「⚠ 需确认」内联标记（警告图标用状态警示色，文字仍用二级色），说明区写清风险/不可逆点；
- 点击仍然只**填入**，状态行显示「该操作可能不可逆，请确认后发送」；
- 任何设置下，危险建议都不会被自动发送。

### 5.6 设置项：每轮条数（Auto / 1–6）

设置里只保留「每轮建议条数」：默认显示 3 条，其余收进「还有 N 条」；选 Auto 时显示模型本轮给出的全部
有效建议（1–6 条），固定值作为展示上限。**点击行为不可配置。**

2026-11-10 决策：**彻底移除 Send 模式**。点击建议永远只把完整指令填入输入框，不再提供「直接发送」，
设置页也没有点击行为行。这样「点击 = 安全动作」成为不随配置变化的固定承诺：误发不可能发生，
用户也不必理解第二个模式。危险建议同样只填入、永不自动发送。

## 6. 卡片内容规则

### 6.1 条数与排序

- **默认展示 3 条**：模型本轮给出 1–6 条有效建议，默认只显示 3 条，其余收进「还有 N 条」；设置可选 Auto（全部显示）或固定 1–6 条上限；
- 模型可标 1 条「推荐」，固定排第一、用 primary 按钮并带「推荐」内联标记；其余保持模型给的顺序；
- 可跳过类建议（stance `optional`，例如“保持现状即可”）固定排最后；所有建议本身都是可选的，因此不显示「可以不做」标记；
- 同轮建议角度不重复（先验证 / 常规推进 / 更用力 / 换一条路 / 可跳过类，同一角度只留一条）。

### 6.2 按钮文案与完整指令

- 按钮上是**短标签**（中文 ≤ 20 字，英文 ≤ 12 词），指向动作本身；
- 悬停或键盘聚焦时，在按钮行下方显示「将填入」+ 该条**完整指令**（真正填入输入框的那段话，两行 clamp），移开/失焦收起；
- 预览文字就是填入指令的开头（前两行）；完整指令包含执行所需的上下文与约束，填入后在输入框里可继续阅读和编辑；
- 预览不是按钮，点击它不会触发填入；触屏没有悬停，点建议直接填入。

### 6.3 更多 / 收起

「还有 N 条」就地展开剩余按钮，再点「收起」；展开状态不记忆。
默认展示 3 条，因此模型给 4–6 条时该入口就会出现；设置选 Auto 时全部直接显示，不出现该入口。

### 6.4 空态与失败态

- 没有合格建议 → **整卡不出现**，过程组行「未显示」+ 可展开原因（§3.5）；
- 用户点状态行「暂不需要」→ 卡片保留并显示「已忽略」，按钮变「恢复建议」；点它恢复，过程组行仍是「已生成」；
- 全局关闭 → 不注册工具，过程组无行、也不出卡；
- 渲染异常 → 静默不出卡，不打扰用户；过程组行按官方状态显示「未显示 / 已中断」。

## 8. 状态与动效

**卡片**

| 状态 | 触发 | 表现 |
|---|---|---|
| hidden | 无合格建议 / 已全局关闭 | 不占空间 |
| idle | 回合结束、卡片出现 | 品牌小标 + 上下文说明 + 控件 + 状态行（右侧「− 暂不需要」） |
| hover / focus | 悬停或键盘聚焦某个建议 | 按钮行下方出现「将填入」+ 该条完整指令（两行 clamp）；控件行不位移；移开/失焦收起；可同时展开/收起说明 |
| filled | 点击后填入草稿 | 该按钮显示一个「已填入」内联标记；状态行「已填入输入框，可修改后发送」；草稿变化后标记消失 |
| conflict | 输入框已有内容 | 控件区为「将填入 / 当前草稿」对比框；状态行左侧「输入框已有内容」与右侧「追加到末尾（primary）/ 替换 / 取消」同一行（窄列可换行），无独立动作行 |
| dismissed | 点了状态行「暂不需要」 | 控件收起；状态行「已忽略」；右侧变「+ 恢复建议」（可恢复）；卡片保留 |
| expanded | 点了「还有 N 条」或展开长说明 | 就地铺开，不跳转、不刷新 |
| unavailable | 输入框不可写 | 按钮禁用；状态行「输入框暂不可用」 |

**过程组行**（与官方 `propose_action` 行同状态机）

| 状态 | 触发 | 表现 |
|---|---|---|
| preparing | 调用准备中 | 「正在准备建议」 |
| running | 调用执行中 | 「正在生成建议」 |
| ok | 调用返回、卡片生成 | 「已生成」+ 摘要；不可展开 |
| error | 调用失败 / 无合格建议 | 「未显示」；可展开原因 +「查看调用」 |
| stopped | 调用被中断 | 「已中断」；可展开原因 +「查看调用」 |

预览设计（2026-11-10 P1）：预览**默认收起**，悬停或键盘聚焦某个建议时，在按钮行下方出现「将填入」+ 该条完整指令
（两行内 clamp），移开/失焦收起。预览出现在控件行之后，因此切换建议只替换文本、不移动按钮；卡片高度随预览出现
短暂增长，不再预留固定高度。触屏没有悬停，点建议直接填入。

冲突态高度（2026-11-10 紧凑化）：动作按钮并入状态行后，748px 宽列实测默认卡 134px → 冲突卡 158px，
差 24px；验收口径为**冲突态与默认态高度差 ≤25px**，以保证状态切换时卡片不跳动。窄列（约 390px）下动作
可能换行，高度需按同一口径单独实测并由视觉证据更新。

动效与官方卡一致：出现/收起克制，`prefers-reduced-motion` 时仅淡入淡出；
显示、展开、折叠、展卡、行展开均不产生任何模型请求。

## 9. 键盘、触屏与可访问性

- `Tab` 顺序：说明折叠「展开/收起」→ 控件区建议按钮 → 「还有 N 条」（展开后为「收起」）→ 状态行右侧「暂不需要」；
  冲突态为状态行内同一行的「追加到末尾 / 替换 / 取消」（依次 Tab）；过程组行可聚焦、整行可点展开（与官方 `DisclosureRow` 的 `expandOnRowClick` 一致）；
- 键盘聚焦到建议按钮时显示「将填入」预览，失焦收起；`Enter/Space` 触发（=填入）；
- 卡片以「下一步建议」作为可读区域名称；建议按钮以完整指令作为 `aria-label`；
- 「已填入」「需确认」「推荐」是带文字的标记，颜色不是唯一线索；
- 触屏：点建议即填入（填入是安全动作，无需二次确认）；冲突对比与展开都可直接点按；预览服务于鼠标与键盘；
- 文字与标记沿用官方卡的 token 层级，暗色模式跟随主题；状态都用文字表达，不依赖动效。

| 元素 | 关系 |
|---|---|
| 官方动作卡 | **同一种卡片、同一个帧**，本卡在其上方；除内容外无任何形态差异。语义不混用：官方卡点击是卡片动作，我们点击是填入输入框。 |
| 工具过程组 | 本调用在组内只占**一行**，与官方 `propose_action` 行同构；折叠过程组时行一起隐藏，展开即可见；行内不出现任何建议按钮。 |
| 交付卡 / 计划卡 / 定时卡 | 位于建议卡之下，顺序稳定；建议卡不抢它们的空间与点击区域。 |
| 输入框 | 点击才写入；写入后聚焦、可编辑；不覆盖已有草稿。 |
| 消息操作行（复制/重试/分支） | 建议卡在其上方，不替代、不遮盖。 |

一屏内卡片组数建议不超过 2（建议卡 + 其他），避免视觉拥挤。

## 11. 行为边界与异常

| 场景 | 理想行为 |
|---|---|
| 本轮没有文本回答（纯工具轮/中断/报错） | 不出卡；过程组行按调用状态显示（未显示/已中断） |
| 建议不相关、太笼统、角度重复 | 不出卡或只留合格条目；宁可少，不凑数；过程组行「未显示」可展开原因 |
| 上下文句缺失/不合格 | 用本地兜底句承接；不出现无说明的控件 |
| 输入框已有用户内容 | 不覆盖，显示「将填入 / 当前草稿」对比；「追加到末尾 / 替换 / 取消」与状态文字同一行，全部只填入 |
| 输入框已有建议填入的内容、用户未改 | 直接替换为新建议，不重复询问 |
| 用户点了同一建议多次 | 只聚焦，不重复插入 |
| 用户发送了消息 | 卡片保留在本轮尾部（与官方卡一致）；草稿清空后「已填入」标记与状态行随之消失；不出现自创的收起摘要 |
| 用户点「暂不需要」 | 卡片控件收起、状态行「已忽略」，按钮变「恢复建议」，卡片保留；点它恢复；过程组行不变（仍是「已生成」） |
| 危险建议 | 只填入 + 警示，永不自动发送 |
| 官方动作卡同时出现 | 建议卡在上，间距正常，两者都可操作；过程组里两行并列、互不干扰 |
| 子代理/团队内部会话 | 不出现 |
| 历史/回放/fork 会话 | 卡片、状态与过程组行保持原样（同官方卡） |
| 改变窗口宽度/窄屏 | 控件换行，卡片不横向溢出 |
| 全局关闭后再打开 | 从下一回合开始出现；历史卡片、状态与过程组行保留 |

## 12. 体验验收清单

- [ ] 卡片出现在回答正下方、官方动作卡上方；与官方卡**同宽、同容器、同说明/状态行**（无可见标题，品牌小标前置；忽略/恢复为状态行右侧带文字按钮；预览按需出现）
- [ ] 工具过程组里该调用只有**一行**：标题 + 状态摘要；正常时不可展开，未显示/中断时可展开原因 +「查看调用」
- [ ] 过程组行与官方 `propose_action` 行同构：同款 DisclosureRow、同款原因框、同款「查看调用」、整行可点展开
- [ ] 过程组行内没有建议按钮；用户点「暂不需要」后行仍是「已生成」
- [ ] 卡片第一屏先看到 1–2 句上下文，再看按钮；上下文句能独立读懂「刚才发生了什么、为什么有这几步」
- [ ] 说明过长时按官方卡规则折叠（展开/收起按钮位置、写法一致），全文不被改写
- [ ] 点击建议：只填入输入框，不发送；光标在末尾；状态行提示「已填入输入框，可修改后发送」，chip 显示单个「已填入」标记
- [ ] 输入框已有内容时，点击不会静默覆盖；对比框显示「将填入 / 当前草稿」，「追加到末尾（primary）/ 替换 / 取消」都可用且只填入
- [ ] 冲突态高度与稳定性：「输入框已有内容」与「追加到末尾（primary）/ 替换 / 取消」在同一行，没有独立动作行；748 列实测默认 134px → 冲突 158px（差 24px），冲突态与默认态高度差 ≤25px；窄列换行情况按同一口径测量
- [ ] 连续点击不同建议不会堆叠文本；用户编辑过的草稿不会被直接覆盖
- [ ] 危险建议有「⚠ 需确认」内联标记（警告图标用警示色），点击后只填入并警示，任何设置下都不会自动发送
- [ ] 默认展示 3 条，其余收进「还有 N 条」；设置可选 Auto 或固定 1–6；推荐项首位并带「推荐」；同一 chip 至多一个内联标记（需确认 > 已填入 > 推荐）；可跳过类建议排最后、不单独标记；同轮角度不重复
- [ ] 悬停/聚焦时按钮行下方出现「将填入」预览（两行 clamp）；预览内容是填入指令的开头，完整内容在输入框可见
- [ ] 点状态行右侧「暂不需要」：控件收起、状态行「已忽略」、按钮变「恢复建议」；再点它：控件恢复、状态回到忽略前
- [ ] 没有合格建议时整卡不出现；过程组行「未显示」可展开原因
- [ ] 刷新/重启/回放后卡片、状态与过程组行保持；显示/展开/折叠不产生模型请求
- [ ] 键盘可完成全部操作；触屏点按即填入；暗色模式正常；中英文案完整
- [ ] 与官方动作卡、交付卡/计划卡/定时卡同屏时顺序稳定、互不遮挡
- [ ] 除已声明的三处差异（无标题、状态行带文字切换、按需预览）外，卡片与过程组行上没有官方卡没有的形态元素（无右上角关闭、无浮层、无自创收起摘要）
- [ ] 点击建议与冲突选择都不存在任何发送路径；设置页没有「点击行为」行（点击永远只填入）

## 13. 设计决策（形态取舍）

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | 落点固定在回答之后、官方动作卡之上 | 建议与回答连续阅读；与官方卡形成上下两层而不争位置 |
| D2 | **严格照抄官方动作卡（三处功能例外）**：同容器、同折叠说明、同控件区、同状态行、同可达性命名；例外为无可见标题（品牌小标代替）、忽略改为状态行右侧带文字按钮、预览按需显示 | 同一种卡片，用户不用学两套交互，也不觉得是外来组件；差异用于品牌身份、减少 footer chrome、点击前预览 |
| D3 | 上下文句必出、不可关闭 | 「先承接再提议」是本功能的立身之本，关掉就退回唐突的按钮流 |
| D4 | 点击只填入、不发送；不提供 Send 模式（2026-11-10 移除） | 给人最后一次修改机会；误发成为不可能事件；「点击=安全动作」不随配置变化 |
| D5 | 输入框冲突时显示「将填入 / 当前草稿」对比，追加为主操作；状态文字与动作同一行、不设独立动作行 | 不覆盖用户已经写下的内容；追加不丢草稿，所以作为默认动作；动作随状态行排列，冲突态只比默认态高约 24px，切换不跳变 |
| D6 | 危险建议只填不发 | 不可逆操作必须由人确认 |
| D7 | 模型同一轮生成上下文与建议（不额外调用） | 形态上要求两者连贯，成本上要求零额外请求 |
| D8 | 每轮最多一张、卡片长期保留、状态行表达结果 | 与官方卡同一规则，不自创"收起摘要"等额外形态 |
| D9 | 不混用官方动作卡的动作语义 | 官方卡是「要不要创建/启用」，我们是「下一步做什么」，混淆会让用户预期错位 |
| D10 | 除已列出的三处功能例外（无标题、状态行带文字切换、按需预览）外，不新增任何官方卡没有的视觉/交互元素 | 严格照抄的边界：右上角关闭、浮层、自创标签样式都不做 |
| D11 | **过程组一行式也严格照抄**：同款 DisclosureRow（标题+状态+摘要）、仅异常可展开原因、同款原因框与「查看调用」、整行可点、行内无操作 | 调用记录只表达调用结果，不承载用户选择；与官方卡观感完全统一 |
| D12 | 文案直接采用官方卡现有文案（暂不需要/已忽略/展开/收起/查看调用；恢复建议沿用 v0.8） | 不自创一套说法，减少学习成本 |
| D13 | 默认展示 3 条 + 「还有 N 条」；Auto 作为设置项 | 首屏稳定、可扫读；需要更多时再展开，Auto 保留给偏好完整列表的用户 |
| D14 | chip 内状态信息用单个文本内联标记（需确认 > 已填入 > 推荐），不用胶囊 Tag；移除「可以不做」标记 | 避免按钮内嵌套胶囊控件；所有建议都是可选的，用排序表达即可 |

## 14. 当下形态与设计哲学（v0.9）

### 14.1 当下的卡片形态（自上而下）

1. **上下文行**：16px 品牌小标（列表 + 星火，实色）在行首，后接 1–2 句上下文；13px / 1.6、`label-secondary`。
   没有可见标题。
2. **控件行**：默认 3 个建议按钮（模型给 1–6 条，其余收进「还有 N 条」）；推荐项用 primary 并带「推荐」，
   当前草稿匹配的项带「已填入」，危险项带「⚠ 需确认」；每个 chip 至多一个内联标记；可跳过类建议排最后，
   不单独标记。
3. **预览**：默认收起；悬停/聚焦建议时在按钮行下方出现「将填入」+ 该条完整指令（两行 clamp），移开/失焦收起。
4. **状态行**：左侧状态文字（已填入 / 输入框已有内容 / 已忽略 / 危险警示 / 输入框暂不可用），右侧一枚带文字的
   ghost 切换按钮：建议态「− 暂不需要」（忽略），已忽略态「+ 恢复建议」。
5. **冲突态**：控件区换成「将填入 / 当前草稿」对比框；状态行左侧「输入框已有内容」，右侧「追加到末尾
   （primary）/ 替换 / 取消」，与状态文字同一行（窄列可换行）；全部只填入。冲突态只比默认态高约 24px
   （748 列实测 134 → 158px，验收 ≤25px）。
6. 卡片没有 footer；过程组里仍是一行「下一步建议 · 已生成 / 未显示…」。

交互与状态：点击 = 只填入输入框，不发送（无 Send 模式）；危险建议永远只填；输入框已有内容时显示对比框；
忽略 = 控件收起、状态行「已忽略」、卡片保留。设置页可改每轮条数（默认 3 / 固定 1–6 / Auto）与重置卡片状态。
触发由常驻系统提示保证：只在有真实后续动作的实质回复里出现。

### 14.2 设计哲学

1. **长在原生上，而不是贴上去。** 容器、圆角、描边、字体层级、按钮规格、状态行全部沿用官方动作卡；
   不新增阴影、边框、浮层或自创图标语言。差异必须由功能推进，而不是由审美偏好。
2. **不命名，只示意份。** 去掉「下一步建议」这个标题：标题会把卡片切成一个独立模块，而它应当是回答的
   自然下一句。身份交给品牌小标，语义交给上下文，可达性交给 `aria-label`。代价是少一个扫读锚点，
   用固定位置的小标 + 必填上下文补偿。
3. **承接先于提议。** 上下文句不是装饰而是必填：先复述刚发生的结果，再给动作，按钮才不会凭空出现。
4. **填而不发，可逆。** 点击只写草稿，绝不自动发送；2026-11-10 起产品不再提供直发选项，误发成为
   不可能事件；危险建议永远只填；忽略只是收起，不删卡、不改历史、不产生模型请求；一切可重置。
5. **安静优先。** 无标题、无 footer、无浮层；忽略/恢复收进状态行右侧的同一枚带文字切换按钮；
   预览默认收起、按需出现在按钮行下方，默认卡片保持稳定高度；每轮最多一张；宁可少给——只在真实后续动作时出现。
6. **状态内聚。** 卡片只保留「内容 + 控件 + 状态」三块；状态文字与忽略/恢复按钮共用一行，冲突态下三个
   动作也收进同一状态行，减少一次性 chrome 与高度跳变。
7. **可回放的事实。** 卡片内容来自会话日志里的 `tool/result.meta`，客户端只做折叠和展示；
   刷新 / 重启 / 回放后按同一份事实重建，视觉调整不依赖瞬时状态。

### 14.3 与内置动作卡的有意差异

| # | 内置动作卡 | 我们 | 理由 |
|---|---|---|---|
| 1 | 16px 可见标题 | 16px 品牌小标 + 上下文行开头 | 降低模块感，让卡片像回答的延伸；`aria-label` 保留「下一步建议」 |
| 2 | 底部 footer「暂不需要」 | 状态行右侧「− 暂不需要 / + 恢复建议」带文字按钮 | 减少一条 footer，把忽略（和可逆的恢复）收进状态区；带文字后可发现性更好 |
| 3 | 无预览 | 默认收起、悬停/聚焦时显示「将填入」 | 点击前可读指令，又不让预览常驻占高；预览在按钮行下方，不移动控件 |
| 4 | 提案动作（act） | 只填入输入框 | 产品目标不同：给下一步并交给人发送；不存在直发路径 |
| 5 | 无标签 | 每 chip 至多一个内联文本标记（推荐 / 已填入 / ⚠ 需确认） | 用文本而非胶囊，避免按钮内嵌套控件；可选建议只排序、不标记 |

其余（容器、折叠说明、按钮尺寸、状态行、过程组行、可达性命名）保持一致。
并排对照图：`design/compare/card-vs-builtin.png`（深色 / 浅色；官方 frame 按源码重建的示意，非内置卡实时截图）。

### 14.4 取舍与待观察

- 无标题降低了首屏扫读速度，依赖上下文句质量；若后续发现扫读困难，可考虑极轻的 eyebrow 文案，而不是
  恢复 16px 标题。
- 预览默认收起（2026-11-10 落地）：默认卡片更矮，但「点击前看到将填入什么」只在悬停/聚焦时生效；
  触屏用户以点击填入为主，看不到预览。若实机发现可发现性不足，可考虑常驻一行摘要。
- 忽略/恢复已改为带文字按钮（2026-11-10 落地），可发现性问题解决；代价是状态行比纯图标略宽。
- 冲突态紧凑化（2026-11-10 落地）：动作并入状态行后宽列高度差 24px（验收 ≤25px）；窄列动作可能换行，
  需与视觉证据一起复核，若超出预算可再压缩对比框行距或调整动作顺序。
- 与内置卡存在 3 处功能差异（无标题、footer 换成状态行文字切换、按需预览）；DSH 升级后需重新对照
  官方 frame，避免版本漂移。

## 附录：形态依据

- 形态基准：**DSH 0.2.2 官方动作卡**（`action-cards` / `client-ui-action-cards`，回答下方的可选动作卡），
  包含两部分：
  1. **卡片**：card 容器、加粗标题、折叠说明（约 260 拉丁字宽、中文双宽、ghost 展开/收起）、控件区、
     `role=status` 状态行、底部 footer 幽灵「暂不需要（Not now）」、以标题命名可读区域、每轮一张、
     展开/折叠不产生模型请求；dismiss 后显示「已忽略（Dismissed）」。
  2. **过程组一行式调用记录**（官方 `propose_action` 行）：一行 `DisclosureRow`（行首标题 + 状态 +
     标题摘要，单行省略）；仅调用失败/被拒时可展开，展开内容是原因 `pre` 框 +「查看调用（Inspect call）」；
     整行可点展开；行内不承载操作；行状态只表达调用结果。
- 本稿的全部形态规则以该基准为准；与官方卡的差异是**内容**（上下文句 + 下一步建议 + 填入输入框），
  以及三处功能例外：v0.6 起无可见标题（改为上下文行行首 16px 品牌小标，`aria-label` 不变）、
  v0.7 起忽略收进状态行右侧（替代 footer，v0.9 起带文字）、v0.9 起预览默认收起、悬停/聚焦时按需出现。
  建议按钮内的状态信息改为单个文本内联标记，不再使用官方 Tag 胶囊。
- 「回合尾部建议」在社区已有多款实践（如 `dsh-nextsteps`、`dsh-suggest-actions`），本稿在这些实践上新增：
  **上下文句、默认填入而非直发、输入框冲突保护、严格复用官方卡卡片与过程组行形态**。
- 实现方案不在本稿范围；技术细节另行成文。
