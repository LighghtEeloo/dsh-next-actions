# 设计：下一步建议

## 要解决的问题

一轮工作结束后，用户常常要自己想清楚下一句该说什么，再把它打出来。模型此时最了解刚发生了什么，
所以由它在收尾时顺手给出几步，用户点一下就能把完整指令放进输入框。

## 体验

```text
助手回答……
[▸ 工具过程组]  下一步建议 · 已生成 · 2

┌───────────────────────────────────────────────────────────┐
│ ▣ 修复已完成，改动集中在 src/api；目前只跑了类型检查。        │
│ [ 跑一下测试 ]  [ 补回归用例 ]  [ ⚠ 推送到远端 ]              │
└───────────────────────────────────────────────────────────┘
```

- **先承接，再提议**：卡片第一行是 1–2 句上下文，说明刚才做了什么、为什么是这几步。
- **最多 3 条**，按模型给出的顺序排列。悬停时显示完整指令（原生提示），不改变布局。
- **点击 = 填入，永不发送**：
  - 草稿为空，或草稿仍是卡片刚填入且未改动的文字 → 整段替换；
  - 草稿里有用户自己的内容 → 在光标处插入「空行 + 指令」，作为一次编辑器编辑，保留 `@` 引用，⌘Z 可撤销。
- **危险建议**：模型标记或本地词表命中时，按钮前加 ⚠，可访问名带「需确认」；同样只填入。
- **只属于最新一轮**：用户发出下一条消息后，上一轮卡片消失；建议只在它承接的回答之后有意义。
- **过程行**：工具过程组里只有一行「下一步建议 · 正在生成 / 已生成 · N / 未显示」，悬停「未显示」可见原因代码。

## 不做的事

不自动发送、不弹确认态、不提供设置页、不保留历史卡片、不做单轮忽略按钮（继续对话卡片自然退场）、
不额外请求模型。全局关闭用 Host 配置 `enabled: false`，此时不注册工具与提示词，零 token。

## 机制

| 部分 | 文件 | 职责 |
| --- | --- | --- |
| Host | `index.js` | 为根 agent 注册 `suggest_next_steps` 与一段常驻提示；`enabled:false` 时什么都不注册 |
| 规范化 | `lib/normalize.js` | 参数 → `{ shown, context, suggestions[≤3] }`：折叠空白、截断、按指令去重、风险词标记。Host 写入 `tool/result.meta`；Client 内联同一份代码重读 meta 或回退到调用参数 |
| Client | `src/client.js` + `src/styles.js` → `client.js` | Conversation Definition 把本工具事件折叠进 `turn.data.get('next-steps')`（native 与 PTC `run_code` 两条通路）；`conversation.chat.turnTail` 渲染卡片；`tool.call.toolview` 渲染过程行 |

最新一轮的判断与 DSH 自身的 TurnTail 相同：`useChat(s => s.timeline.turnOrder.at(-1))`。取不到时视为最新，卡片照常显示。

外部插件不能 require Harness Client 包，所以卡片沿用官方动作卡的边框、圆角、底色与字号，
类名用 `dshns-` 前缀，只引用 `--dsw-*` 主题 token。出现时用 CSS `grid-template-rows` 展开，避免回答被一帧顶起；
`prefers-reduced-motion` 下不做动画。
